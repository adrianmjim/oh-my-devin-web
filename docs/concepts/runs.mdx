---
title: "Runs"
description: "What happens when omd run executes a role: one headless session, strict validation, a single repair attempt, and a classified outcome."
---

`omd run <role> "<task>"` executes one role end to end with no human
interaction and terminates in an outcome report. A run either succeeds — the
role's declared artifact validates against its schema within budget — or fails
in exactly one of three ways.

## Lifecycle

1. **Resolve the role.** The role and its schema are loaded and validated. An
   unresolvable or malformed role is rejected before any session starts, as a
   usage error.
2. **Compile the contract.** The role's tools, permissions, and instructions
   are compiled into a per-invocation configuration bundle for the engine.
3. **Open a headless session.** `omd` launches a Devin session with the task
   and the compiled bundle and lets the role work within its turn budget.
4. **Validate the artifact.** After the session, the declared artifact is
   strictly validated against the role's JSON Schema.
5. **Repair once, if needed.** If validation fails and budget remains, `omd`
   resumes the same session exactly once, feeding back the validation report.
   The repair turn draws from the same `omd-max-turns` budget.
6. **Classify and report.** The run ends as success or as one classified
   failure tier, reported in human-readable form or as JSON with `--json`.

## Under the hood

Each turn is one non-interactive invocation of the Devin CLI — `devin -p` with
the compiled `--agent-config` bundle, resumed with `--resume` so session memory
carries across turns. Sessions are namespaced by working directory, so run one
`omd` session per directory at a time to keep session identity unambiguous.

## Failure tiers

Every failed run maps to exactly one tier, with a fixed exit code:

| Tier | Meaning | Exit code |
| ---- | ------------------------------------------------------------------- | --------- |
| 1 — deny | The session hit a `deny` rule — a contract red line | `2` |
| 2 — invalid artifact | The artifact is missing or fails schema validation after repair | `3` |
| 3 — budget | Turns or wall-time ran out before a valid artifact existed | `4` |

When more than one condition holds, the higher tier wins: deny over invalid
artifact over budget. Usage errors exit with `64` before any session starts;
an unexpected engine failure exits with `1`.

## Reports

The human report is a fixed block — outcome, role, task, engine, session,
artifact validity, turns used, wall time, and a tier detail line. With
`--json` the run emits a single object with camelCase fields: `role`, `task`,
`engine`, `sessionId`, `outcome`, `failureTier`, `exitCode`, `turnsUsed`,
`maxTurns`, `wallTimeMs`, `artifactPath`, `artifactValid`,
`validationErrors`, `denyRule`, and `repairAttempted`.
