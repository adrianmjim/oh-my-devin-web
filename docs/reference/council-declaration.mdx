---
title: "Council declaration"
description: "Every key of a council declaration — seats, deliberation tunables, authority — and the position contract each seat's role must satisfy."
---

A council is one YAML declaration at `.devin/councils/<name>.yaml`. A
malformed declaration is rejected as a usage error before any seat session
starts.

## Keys

| Key | Required | Type | Meaning |
| -------------- | -------- | -------------- | -------------------------------- |
| `name` | yes | string | The council's name |
| `seats` | yes | non-empty list | The deliberating seats |
| `deliberation` | yes | mapping | Round and consent tunables |
| `authority` | no | mapping | What a passed closure is worth |

### Seats

| Key | Required | Type | Default | Meaning |
| ------------ | -------- | ------- | ------- | ------------------------------------------ |
| `role` | yes | string | — | A role discovered in the project's catalog |
| `lens` | yes | string | — | The perspective the seat is accountable for |
| `proposer` | no | boolean | `false` | This seat drafts and revises the proposal |
| `contrarian` | no | boolean | `false` | This seat is framed to seek the strongest counter-argument |
| `model` | no | string | role's model | Per-seat model override, a decorrelation lever |

Seat identifiers are derived automatically: a seat is named after its role,
or `<role>-<n>` when the same role fills several seats.

### Deliberation

| Key | Required | Type | Default | Meaning |
| -------------------- | -------- | ---------------- | ------- | -------------------------------- |
| `rounds_cap` | yes | positive integer | — | Maximum deliberation rounds |
| `blocking_threshold` | no | `low` \| `medium` \| `high` \| `critical` | `high` | Minimum severity at which an in-lens objection blocks consent |
| `wall_time_ms` | no | positive number | unset | Wall-time cap for the whole deliberation |

### Authority

| Key | Required | Type | Default | Meaning |
| ------------ | -------- | ---------------------- | ------- | ---------------------------------------- |
| `on_consent` | no | `human` \| `proceed` | `human` | `human` escalates a pass for a human signature; `proceed` lets it flow onward |

There is no key that suppresses dissent: objections below the blocking
threshold are still recorded and carried into the decision record.

## The seat position contract

Each non-proposer seat's role must write its declared output artifact as a
position object. `omd` parses it with the following shape:

| Field | Applies to | Type | Meaning |
| ----------------- | -------------------------- | -------------- | ------------------------------ |
| `kind` | all | `objection` \| `preference` \| `clarification` | The position's type |
| `severity` | objection, preference | `low` \| `medium` \| `high` \| `critical` | How strongly the concern weighs |
| `domain` | objection, preference | string | The area the concern belongs to |
| `concern` | objection, preference | string | The concern itself |
| `assumptions` | objection, preference | list of strings, optional | What the position assumes |
| `reconsider_when` | objection, preference | list of strings, optional | Conditions that should reopen the decision |
| `questions` | clarification | list of strings | Questions to resolve before positioning |

A proposer seat writes the proposal document as its artifact instead and casts
no position.

## Example

```yaml .devin/councils/design-council.yaml
name: design-council
seats:
  - role: architect
    lens: overall-design
    proposer: true
  - role: security
    lens: threat-model
  - role: sre
    lens: operability
    contrarian: true
deliberation:
  rounds_cap: 3
  blocking_threshold: high
authority:
  on_consent: human
```
