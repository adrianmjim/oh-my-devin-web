Running `omd` with no arguments, `--help`, or `-h` prints the usage banner:

```text
omd — an organizational layer over the Devin CLI

Usage:
  omd run <role> "<task>" [--json]   Run a role against a task end to end
  omd doctor                         Check the local runtime contract
  omd roles list [--json]            List the project's roles
  omd roles show <role> [--json]     Show a role's expanded contract
  omd setup [--scope=<parts>]        Install the in-session layer (parts: rules,roles,skills,hooks)
  omd plugin build [--out <dir>]     Build the installable devin plugin bundle
  omd team run <team> "<task>"       Run a team pipeline (architect → executor → reviewer)
  omd council run <c> "<question>"   Run a deliberation council [--proposal <path>] [--then <team>] [--sign] [--json]
  omd mode <set|clear> [<mode>]      Set or clear the persistent mode state read by the session hooks
```

Two conventions hold across the surface. Commands that support `--json` emit a
single JSON object with camelCase fields instead of the human report. A usage
error prints `usage error: <message>` to stderr (or
`{"error": "...", "exitCode": 64}` when `--json` is present) and exits `64`;
any unexpected error prints `error: <message>` and exits `1`.

## omd run

```bash
omd run <role> "<task>" [--json]
```

Runs one role against a task end to end: compile the role's contract, open a
headless session, validate the declared artifact, repair at most once, and
report. Both arguments are required and the task must be non-empty. There is no
per-run model flag — the role's declared `model` always applies.

Exits `0` on success, `2` on a deny hit, `3` on an invalid artifact, `4` on
budget exhaustion. See [Runs](/docs/concepts/runs) for the lifecycle and the
JSON report fields.

## omd doctor

```bash
omd doctor
```

Runs the five runtime-contract checks — `devin-cli`, `devin-version`,
`agent-config`, `headless-surface`, `node-runtime` — printing
`[pass|warn|fail] <check>: <message>` per line. Exits `1` if any check fails;
warnings alone exit `0`.

## omd roles

```bash
omd roles list [--json]
omd roles show <role> [--json]
```

`list` scans `.devin/agents/*/AGENT.md` and prints one line per role — the
name and the first line of its prompt. Roles that fail to parse are reported
on stderr as `! <name>: <message>` without hiding the valid ones; an empty
catalog prints `No roles found.` and exits `0`. With `--json`, each entry
carries `name`, `output`, `schema`, `maxTurns`, `context`, `engine`,
`agentType`, and `model`.

`show` prints the named role's expanded contract — name, engine, agent type,
model, tools, permissions, artifact, schema, budgets, and prompt summary. With
`--json` the fields are `name`, `engine`, `agentType`, `model`, `tools`,
`permissions`, `output`, `schema`, `maxTurns`, `context`, `wallTimeMs`, and
`promptSummary`. An unknown role is a usage error.

## omd setup

```bash
omd setup [--scope=<parts>]
```

Installs the in-session layer into the current project and lists every file it
wrote. `--scope` takes a comma-separated subset of `rules,roles,skills,hooks`
and must use the `--scope=` form; without it, all four components are
installed.

<Warning>
  Files are written unconditionally — an existing `AGENTS.md` or any other
  colliding file is overwritten.
</Warning>

## omd plugin build

```bash
omd plugin build [--out <dir>]
```

Writes the installable Devin plugin bundle — `.devin-plugin/plugin.json`,
`AGENTS.md`, and the skills — and prints the absolute output directory.
`--out` (space or `=` form) overrides the default output directory
`.omd/plugin`.

## omd team run

```bash
omd team run <team> "<task>" [--json]
```

Runs the team declared at `.devin/teams/<team>.yaml` through the three-stage
pipeline with a human gate after each stage. If a `requirements.md` exists at
the project root, the task is prepended to it to form the requirements
artifact. Exits `0` when the pipeline reaches `done`, `1` when it halts. See
[Teams](/docs/concepts/teams) for gates, handoffs, and the JSON report.

## omd council run

```bash
omd council run <council> "<question>" [--proposal <path>] [--then <team>] [--sign] [--json]
```

Runs the council declared at `.devin/councils/<council>.yaml` against a
question. `--proposal` attaches a free-form proposal file; without it, the
proposer seat drafts one. `--then` names a team to bridge into on an
authorized pass, and only takes effect together with `--sign`, the human
sign-off. Valued flags accept both `--flag value` and `--flag=value`.

Exits `0` on `passed`, `5` on `blocked`, `6` on `bankrupt`. Every closure
writes a decision record under `.omd/deliberations/`. See
[Councils](/docs/concepts/councils) for the deliberation protocol.

## omd mode

```bash
omd mode set <mode>
omd mode clear
```

`set` writes the persistent mode state to `.omd/mode.json` and prints
`mode set: <mode>`; valid modes are `autopilot`, `ralph`, `team`, `plan`, and
`verify` (`deep-dive` is a skill without persistent state). `clear` removes
the state — silently succeeding if none exists — and prints `mode cleared`.

## Exit codes

| Code | Meaning |
| ---- | ------------------------------------------------------------------ |
| `0` | Success — including a council that closed `passed` |
| `1` | Unexpected error; `omd doctor` with a failing check; a halted pipeline |
| `2` | Run failure tier 1 — deny hit |
| `3` | Run failure tier 2 — invalid artifact |
| `4` | Run failure tier 3 — budget exhaustion |
| `5` | Council closed `blocked` |
| `6` | Council closed `bankrupt` |
| `64` | Usage error — rejected before any session starts |
